# Setting up a prover host

A rollup node settles on Solana only when a prover posts a proof for each batch. The prover runs ZisK 1.3.1-alpha on
one NVIDIA GPU. This page sets up a fresh Ubuntu host for it: the ZisK GPU build, its proving keys, the system
limits and the Docker runtime. The script that does it is
[`deploy/rollup/prover/setup-prover-host.sh`](../deploy/rollup/prover/setup-prover-host.sh), and every step is
described below so you can run it by hand instead.

You do not need a prover host to run the node itself, only to settle roots. See
[the prover is required for settlement](../deploy/rollup/README.md#the-prover-is-required-for-settlement).

## What the host needs

| Need | Value |
| --- | --- |
| Operating system | Ubuntu 22.04 or later, x86_64 |
| GPU | The setup script accepts one NVIDIA GPU with about 32.2 GB of memory or more. The final proof step asks for about 30 GB, so a 24 GB card is not enough. While the prover proved a nearly empty batch on a 96 GB card, about 95 GB of the card's memory showed as in use. That is how much the prover held, not the least a batch needs. Smaller cards have not been tested with this release. |
| NVIDIA driver | 525.60.13 or later, which is ZisK's own minimum. The prover image is built on CUDA 12.9, so a recent driver is the safer choice. |
| Disk | By default, about 27 GB is downloaded below the install directory (proving key 5.1 GB, PLONK key 21.9 GB). The archives are deleted after unpacking. After the setup's `check-setup` step, the proving key directory measured 21 GiB and the PLONK key directory 26 GiB (`du -sh`), 47 GiB (about 50 GB) together. The first proof adds its cache on top; a CPU host measured 102.1 GB in total after one. Plan for 125 GB free at the install directory. |
| Memory | The proving library reports 24.7 GB for its main working buffer and 5.6 GB for the recursion steps, for a batch of about 3.0 million steps. The peak memory of the whole process was not recorded on ZisK 1.3.1-alpha. On ZisK 1.2.0-alpha the peaks were 37.5 GB for the STARK step and 88.4 GB for the PLONK step, for a batch of 10 empty blocks. The GPU host that proved the devnet batches had 176 GB of RAM; its peak use was not recorded. Plan for at least 128 GB. |

## What was measured

Every figure in the table below was measured on a CPU-only host with 32 vCPUs (Intel Xeon, 2.8 GHz) and 135 GB of RAM.
A GPU host also writes files of its own when it first proves; how much disk they take has not been measured.

| What | ZisK 1.3.1-alpha, CPU host |
| --- | --- |
| Download | 5.1 GB for the proving key and 21.9 GB for the PLONK key, 27.0 GB together |
| Unpacked | about 42 GB (proving key 15.8 GB, PLONK key 26.2 GB) |
| After the earlier `check-setup` command generated the constant trees | 62.4 GB |
| After the first proof | 102.1 GB (60.2 GB of it are `*.consttree` files) |
| Constant trees generated by that earlier `check-setup` command | about 3 minutes |
| First proof of one 3,027,017-step batch on the CPU, including the PLONK wrap | about 20 minutes |
| Of which the PLONK wrap | 205 seconds |

The two `check-setup` rows were measured with an earlier command, not the one the setup runs now. With the setup's command, a host measured 21 GiB for the proving key directory and 26 GiB for the PLONK key directory (`du -sh`) after the step; the time it takes has not been measured.

On a host with one 96 GB RTX PRO 6000 (Blackwell) GPU, 48 CPU cores and 176 GB of RAM, a proof of a nearly empty
batch took about 17 seconds, including the PLONK wrap. About 95 GB of the card's memory showed as in use while the prover ran.
Larger batches have not been timed on a GPU.

The first CPU proof included about 2.5 minutes generating more constant trees and about 45 seconds loading the
recursive setup. A later proof on the same host skips that one-time generation. The same CPU batch was not timed on
the GPU host. `cargo-zisk prove --plonk -y` checks the wrapped proof with `snarkjs` after the wrap and
fails without it ("Failed to execute snarkjs"); the prover image carries it.

## Run the script

Install an NVIDIA driver first if the host has none (`sudo ubuntu-drivers install`, then reboot). Then, as root:

```
sudo ZISK_HOME=/opt/zisk bash deploy/rollup/prover/setup-prover-host.sh
```

`ZISK_HOME` is where ZisK and the keys go. It becomes `ZISK_HOME` in your rollup `.env`, and the compose file mounts it
read-only into the prover container. Put it on a disk with room for the keys.

The script skips the key download when the installed keys match the manifest. It refuses mismatched keys without
replacing them. A failure starts with a name and exits non-zero:

| Name | Meaning |
| --- | --- |
| `NotRoot` | Run it with `sudo`. |
| `UnsupportedPlatform` | ZisK's GPU build runs on Linux x86_64 only. |
| `NoGpuDriver` | `nvidia-smi` is missing. Install an NVIDIA driver, reboot, and retry. |
| `GpuDriverTooOld` | The driver is below 525.60.13. Update it and retry. |
| `GpuMemoryTooSmall` | The largest GPU has less than the default threshold of about 32.2 GB. Use a GPU with enough memory. |
| `NotEnoughDisk` | Free more space at `ZISK_HOME`, or set `MIN_FREE_GB` if you know better. |
| `ZiskupFailed` | An installer, archive download, unpack, or key setup step failed. Fix the failed step and retry. |
| `ZiskupHashMismatch` | The `ziskup` file does not hash to the sha256 pinned for this release. The script does not run it. If it is the installer of another release, move it away and run the script again. |
| `ZiskPinMissing` | A required hash or commit is missing from the pin files. Restore the pin for this release before installing. |
| `KeysUrlMissing` | The checked `ziskup` has no usable key archive URL and `KEYS_URL_BASE` is unset. Set `KEYS_URL_BASE` to the archive directory. |
| `DownloadDirInsideZiskHome` | `DOWNLOAD_DIR` is inside `ZISK_HOME`. ziskup clears `ZISK_HOME` when it installs, so the checked archives would be gone before they are unpacked. Leave `DOWNLOAD_DIR` unset (it defaults to a directory beside `ZISK_HOME`) or set it outside. |
| `KeyArchiveMissing` | An archive is absent from `DOWNLOAD_DIR` during `--check-archives`. Run the install mode to fetch it. |
| `KeyArchiveHashMismatch` | A key archive differs from its pinned sha256. Remove the bad archive and retry the download. |
| `BinaryHashMismatch` | `cargo-zisk` or `cargo-zisk-dev` differs from its pinned GPU binary. Move `ZISK_HOME` away and reinstall. |
| `KeysShaMismatch` | The installed keys do not match `keys.sha256`. Move the key directory away and reinstall the pinned set. |
| `NotGpuBuild` | `cargo-zisk` or `cargo-zisk-dev` is missing, or `cargo-zisk` reports a non-GPU build. Move `ZISK_HOME` away and reinstall. |
| `WrongZiskVersion` | The installed `cargo-zisk` reports the wrong release or commit in its own version line. Reinstall the pinned release. This line can catch a wrong install, but a substituted binary can print a false version; the binary hash check covers that. |
| `MemlockNotUnlimited` | The locked-memory limit is not unlimited in this shell. Log out and back in, then retry. |
| `NoNvidiaDockerRuntime` | Docker is missing or has no `nvidia` runtime. Install or configure Docker and the NVIDIA container toolkit. |

All check modes leave the host unchanged. Pass one of these flags to the script:

| Flag | Check |
| --- | --- |
| `--check` | Check the GPU, both GPU binary hashes, the `cargo-zisk` version line, the installed keys, memlock, and Docker's NVIDIA runtime. |
| `--check-ziskup` | Check only the installer at `ZISKUP_BIN` (default `/usr/local/bin/ziskup`) against its pinned sha256. |
| `--check-binaries` | Check only the installed `cargo-zisk` and `cargo-zisk-dev` GPU binary hashes. |
| `--check-archives` | Check that both archives exist in `DOWNLOAD_DIR` and match their pinned sha256. |

## What the script does

1. **Checks the GPU.** It reads the driver version and the memory of the largest GPU with `nvidia-smi`.
2. **Installs the system packages** ZisK's binaries load: OpenMPI, OpenMP, GMP and libsodium, and rustup (minimal, with no default toolchain), which ziskup needs to install ZisK's toolchain.
3. **Removes the locked-memory limit.** `cargo-zisk` locks a large amount of memory while it proves and does not run
   under the default limit. The script writes `memlock unlimited` to `/etc/security/limits.d/` for login sessions and
   `DefaultLimitMEMLOCK=infinity` to the systemd configuration for services. Log out and in again for it to apply to
   your shell. The prover container sets the same limit itself in the compose file.
4. **Installs Docker and the NVIDIA container toolkit,** then registers the `nvidia` runtime with Docker and restarts it.
5. **Installs ZisK 1.3.1-alpha and its keys.** When keys need installing, the script downloads `ziskup` if it is absent
   and checks its sha256 before running it. It also checks an installer already present on the host. The installer pin is in
   [`deploy/rollup/guest-build/zisk/1.3.1-alpha.env`](../deploy/rollup/guest-build/zisk/1.3.1-alpha.env).

   The script gets the key archive base URL from the checked `ziskup`, unless `KEYS_URL_BASE` overrides it. It
   downloads the proving-key and PLONK-key archives itself and checks both against the sha256 values in
   [`deploy/rollup/prover/host-pins/1.3.1-alpha.env`](../deploy/rollup/prover/host-pins/1.3.1-alpha.env). If either hash
   fails, neither archive is unpacked. It then runs:

   ```
   ziskup -v 1.3.1-alpha --gpu --nokey -y --prefix "$ZISK_HOME"
   ```

   `--nokey` makes `ziskup` install the binaries without downloading keys. The script checks the installed
   `cargo-zisk` and `cargo-zisk-dev` GPU binaries against their pinned sha256 values before the script runs either. It unpacks
   the proving key and the PLONK key, then runs `cargo-zisk-dev check-setup` on both, with aggregation on, to generate
   their constant trees and, on a GPU host, the GPU constant files every proof step needs. The command is:

   ```
   cd "$ZISK_HOME" && ZISK_HOME="$ZISK_HOME" "$ZISK_HOME/bin/cargo-zisk-dev" check-setup \
     --proving-key "$ZISK_HOME/provingKey" --proving-key-plonk "$ZISK_HOME/provingKeySnark" --plonk --gpu \
     && touch "$ZISK_HOME/.check-setup-done-1.3.1-alpha"
   ```

   The generated files are not part of the key hash, so the script writes a marker file, `.check-setup-done-<release>`
   beside the key directories, only after the command succeeds. If the command fails or is killed, run the setup again:
   it sees the keys already match, skips the download, and runs the command again because the marker is missing. The last
   check refuses with `ConstantFilesMissing` until the marker is there.
   `--prefix` selects the install directory. `ziskup` reads `ZISK_DIR` but only exports `ZISK_HOME`.

   There is a gap before the binary check: `ziskup` downloads the ZisK binary bundle without a hash check and runs
   `cargo-zisk toolchain install` from it first. The script does not check the rest of that bundle:
   for example `zisk-worker`, `zisk-coordinator`, `ziskemu`, `libziskc.a`, `libziskclib.a`, or the ZisK sources, nor the
   toolchain that `cargo-zisk toolchain install` downloads.
6. **Prepares the proving cache** at `$ZISK_HOME/cache`, owned by the user the prover container runs as (uid 999).
7. **Checks the result.** Both GPU binaries must match their pins. `cargo-zisk` must report the GPU build, release
   1.3.1-alpha and the first seven digits of the release's commit (`306a9c9`). The proving keys must match
   `keys.sha256`. The memlock limit must be unlimited and Docker must have the `nvidia` runtime.

## Check that cargo-zisk is the GPU build

```
$ZISK_HOME/bin/cargo-zisk --version
cargo-zisk 1.3.1-alpha [gpu] (306a9c9 ...)
```

The tag in square brackets tells the two builds apart: `[gpu]` or `[cpu]`. The GPU build only uses the GPU when you
pass `-g`, and the prover does that for you when its config says `gpu = true`. The CPU-only build has no `-g`.

The prover never proves on the CPU by accident. `gpu` is a required line in `prover.toml`, and the rendered config
says `gpu = true`. With it, the prover refuses to start by name, `GpuBuildRequired`, when the `cargo-zisk` it finds is
not the GPU build. A config without a `gpu` line is refused too. To prove on the CPU on purpose, which takes hours per
batch, set `gpu = false`.

## The proving keys

`keys.sha256`, next to the script, holds one hash for each key directory. The hash covers every file's name and
content, so an added, removed, renamed or changed file shows up. It is pinned to the 1.3.1-alpha key set that Rome's
proofs are made with. It was made from the keys of a CPU host, and the `*.consttree`, `*.consttree_gpu` and `*.const_gpu` files, which are the
ones that differ between a CPU and a GPU install (a GPU install writes one `*.const_gpu` file per circuit: 135 of them under
`provingKey`, and under `provingKeySnark/recursivef` the files `recursivef.const_gpu`, `recursivef.consttree` and
`recursivef.consttree_gpu`), are left out of the hash, so a GPU host's keys hash the same. The prover container checks it before every start, and you can check it yourself:

```
ZISK_HOME=/opt/zisk bash deploy/rollup/prover/check-keys.sh
```

It prints `OK` for each directory and exits 0. Any other exit code names the reason: 10 not populated, 11 manifest
not pinned, 12 mismatch, 13 manifest missing.

If the keys on your host are a different set (a newer release, say), the check refuses with `KeysShaMismatch` and the
prover does not start. Do not re-pin to make it pass. Install the release the manifest was made for. Pin your own
manifest with `--write` only if you are deliberately running a different release.

## Use the host for a rollup

Set these in the `.env` of `deploy/rollup`: `PROVER=on`, `ZISK_HOME` (the directory above), `VKEY_JSON` and `ELF_DIR`.
Then run `./rollup init` and `./rollup up`. The first `up` builds the prover image from this repository; the image
holds the prover and its runtime libraries, not ZisK or the keys. The compose file mounts `ZISK_HOME` read-only at
`/opt/zisk`, gives the container an unlimited memlock limit and reserves the NVIDIA GPU for it.

To confirm the GPU is visible from inside the container, once the image exists:

```
docker run --rm --gpus all --entrypoint nvidia-smi rome-zk-prover:local
docker run --rm --entrypoint /opt/zisk/bin/cargo-zisk -v "$ZISK_HOME:/opt/zisk:ro" rome-zk-prover:local --version
```

The first prints your GPU. The second must show `[gpu]`.
